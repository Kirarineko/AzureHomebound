# 修改 HTML 批注前先重读文件，改后复查注释清零

本项目的创作修改循环是：用户在大纲/正文中插入 `<!--...-->` 批注，AI 逐条处理并删除注释。实践中反复验证过两个失败模式，对应两条操作规则：

1. **改前重读**：用户会在两轮对话之间手动编辑文件（增删内容、调整措辞）。若凭上一轮记忆构造 edit 的 oldString，会因与磁盘当前内容不匹配而失败（"oldString not found"）。处理每条批注前，先 Read 目标文件（或至少批注附近的行段），拿到精确文本后再 edit。
2. **改后复查**：多处批注共存时，单次 edit 只删自己处理的那条；全部处理完后必须重读全文，确认没有任何 `<!--` 残留。曾出现"改正文成功但注释串还留在原文里"的情况（edit 只替换了正文部分、注释部分漏删），只有复查全文才能发现。

应用时机：任何"按批注修改文件"的任务。批注清零 = 本轮修改完成的判据。
